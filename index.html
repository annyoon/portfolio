신규 기능 · 단독 담당

인재 탐색 리포트 신규 설계 및 개발

Overview

인사 발령 및 인재 관리를 위해 특정 인원의 역량을 데이터 기반으로 파악하는 것이 필요했습니다. 이러한 니즈에 따라 새로운 ‘탈렌트 세션’ 기능을 오픈하게 되었습니다.

‘탈렌트 세션’은 과거 평가 이력, 성과 목표, 동료 피드백 등의 데이터를 통합하여 한눈에 보여주는 대시보드형 리포트 페이지로, 해당 신규 기능의 프론트엔드 설계 및 개발을 단독으로 담당했습니다.

Key result

  • 사용자 페이지와 관리자 설정 페이지를 108개 파일, 약 12,000줄 규모로 신규 개발
  • 그래프 및 테이블 기반 다양한 데이터 시각화와 반응형 UI 구현
  • 관리자 설정을 섹션 독립형 구조로 설계하여 확장성과 개방-폐쇄 원칙(OCP) 적용

Problem & Solution

01라이브러리 제약을 극복한 차트 구현

평가 결과를 한눈에 보여주기 위해 점수(막대)와 등급(라인)을 한 차트에 겹쳐야 했습니다. 하지만 ECharts의 기본 Line 시리즈는 카테고리 묶음의 중앙에만 점을 찍을 수 있어서, 개별 막대 위에 등급 라인을 정확히 맞출 수 없다는 한계가 있었습니다.

로우레벨 옵션을 활용한 돌파구

제약이 많은 기존 Line 시리즈를 과감히 제거하고, Bar 시리즈 안에 ECharts의 로우레벨 옵션인 markLine과 markPoint를 조합하여 라인 그래프처럼 보이도록 직접 구현했습니다. Bar 사이 특정 좌표(중앙)를 계산하고, 그 사이를 짧은 직선(markLine)으로 이어 붙여 연속된 라인처럼 배치했습니다. 각 지점에는 커스텀 심볼(markPoint)로 라인 위의 점을 표시했습니다.

라이브러리가 기본적으로 제공하지 않는 시각화 요구사항을 100% 충족

02확장성을 고려한 관리자 설정 페이지 설계

관리자 페이지는 여러 설정 섹션으로 이루어져 있는데, 고객사 요청이나 고도화에 의해 섹션이 계속 늘어나는 구조입니다. 사내의 비슷한 설정 페이지들은 컨테이너 하나가 모든 상태, 검증, 저장 로직을 들고 있어서 지나치게 길고, 기능이 추가되면서 복잡도가 급격히 상승한 구조였습니다. 따라서 향후 추가될 새로운 설정 섹션에 유연하게 대응할 수 있는 ‘확장성’을 메인 키워드로 작업했습니다.

공통 프레임은 흐름만 갖고, 내용은 주입받기 (템플릿 메서드 + 전략 패턴)

모든 설정 섹션은 ‘수정 모드 진입 → 수정 → 검증 → 저장 → 수정 종료’ 또는 ‘취소 → 초기화’라는 흐름을 따릅니다. 이 흐름의 뼈대를 공통 컴포넌트인 FormBox가 Formik과 함께 갖고, 섹션마다 다른 검증 규칙과 저장 방식은 각 섹션이 주입합니다. FormBox는 어떤 섹션을 감싸고 있는지 모르고, 받은 함수를 실행 후 저장에 성공하면 onComplete 콜백을 호출해 수정을 종료합니다.

새 섹션을 붙일 때 공통 코드 수정 없이 폼 컴포넌트 하나와 훅 하나만 추가하여 OCP 확인

섹션별 관심사 분리와 계층 구조 설계

화면 표시, 서버 통신, 비즈니스 로직, 세션 생명주기가 한 컴포넌트에 섞이지 않게 역할별 계층으로 분리했습니다.

  • 화면 (섹션 폼): 입력 UI만 그립니다.
  • 데이터 (섹션별 커스텀 훅): 백엔드와 협의해 API를 섹션 단위로 나누고, 각 훅이 담당 섹션의 API만 호출합니다.
  • 비즈니스 로직 (순수 함수): 검증 규칙과 설정 완료 여부를 순수 계산으로 분리했습니다.
  • 생명주기 (커스텀 훅): 세션의 시작·마감·복사·삭제·복구와 작업 진행률 추적을 따로 맡습니다.

컨테이너 비대화를 막고 팀원들이 특정 기능의 로직을 바로 파악

수정 상태를 각 섹션 안에 두어 리렌더링 최적화

수정 모드 여부를 컨테이너가 아니라 각 FormBox가 갖게 하고, 필드는 children으로 받아 Context로 해당 상태만 읽도록 했습니다. 한 섹션을 수정해도 다른 섹션은 리렌더링되지 않고, 같은 섹션 안에서도 수정 모드를 읽는 필드만 갱신됩니다. 또한 첫 저장 시도 이후에만 검증하도록 하여 입력 도중의 렌더링을 막았습니다.

무거운 섹션이 늘어나도 수정 시 반응성 유지

전면 리팩토링 · 단독 담당

인사평가 목록 페이지 전면 개편

Overview

인사평가 목록 페이지는 임직원이 본인에게 할당된 평가 프로세스를 확인하고, 각 평가의 응답 페이지나 결과 페이지로 진입하는 서비스의 핵심 게이트웨이입니다. 수십~수천 명 규모 기업의 평가 진행 현황이 모두 이 페이지를 거칩니다.

기존 화면의 사용성 문제가 여러 번 리포팅되었고, 복잡하게 얽힌 레거시 구조 때문에 기능 추가 비용이 큰 상태였습니다. 이를 해결하기 위해 UI/UX 리디자인 구현과 전면 리팩토링을 함께 진행했고, 기획·디자인 협의부터 구현, 레거시 제거, 배포까지 프론트엔드를 단독으로 담당했습니다.

Key result

  • 약 5,000줄 규모의 클래스형 JSX 레거시를 함수형 TypeScript로 전면 재작성
  • 단일 컨테이너(약 1,300줄)를 탭 컴포넌트 3개, 커스텀 훅 7개, 순수 함수 모듈 5개로 분리
  • 흩어져 있던 고객사별 커스텀 로직을 단일 커스텀 훅으로 통합해 Feature Flag 패턴 구현

Problem & Solution

015,000줄 레거시를 안전하게 전환하기

기존 클래스형 컴포넌트에는 사용자 권한(조직장/평가자/검토자), 평가 상태별 노출 여부, 평가자 익명 처리 등 가장 민감한 비즈니스 로직이 한 파일에 몰려 있었습니다. 문서화되지 않은 예외 케이스가 많았고, 작은 실수 하나가 데이터 노출 사고로 이어질 수 있었습니다. 또한 목록이 길어질수록 다음 페이지를 불러올 때 스크롤이 버벅이는 렌더링 성능 문제도 안고 있었습니다.

로직 전수 조사와 히스토리 문서화

코드를 옮기기 전 일주일간 레거시 동작을 권한별·상태별 비즈니스 플로우 단위로 문서화하고 팀 공유로 검증받았습니다. 가장 민감한 익명 조건 조합은 ‘비공개’, ‘본인 정보만 노출’, ‘전체 공개’ 세 가지로 수렴시키고, 하나의 컴포넌트 안에서 우선순위에 맞게 판단하도록 구현했습니다.

권한 오류나 노출 관련 이슈 0건으로 리팩토링 완료

대량 데이터 렌더링 성능 개선

기존 목록은 무한 스크롤로 새 페이지가 추가될 때마다 이미 그려진 평가별 테이블까지 모두 다시 렌더링되었습니다. 새로 작성하면서 목록이 append-only 구조라는 점을 이용해 평가별 테이블(MUI DataGrid)을 커스텀 비교 함수를 넣은 memo로 감쌌고, 새 페이지가 추가되어도 이미 그려진 테이블은 리렌더링하지 않도록 했습니다.

목록이 길어져도 다음 페이지 로딩 시 스크롤이 부드럽게 유지

V1/V2 병행 배포로 무중단 전환

레거시를 바로 지우지 않고 고객사 단위로 분기해 신규 페이지를 배포했습니다. 모든 고객사가 신규 페이지로 전환된 것을 확인한 뒤 분기 코드, V1 전용 파일 10개, 관련 플래그를 일괄 제거했습니다.

언제든 되돌릴 수 있는 상태를 유지하면서 서비스 중단 없이 전환

02곳곳에 흩어진 고객사별 커스텀 로직 통합

고객사 요구사항이 쌓이면서 기능을 가르는 분기가 코드 곳곳에 퍼져 있었습니다. 팀원마다 다른 위치에 분기를 추가하며 중복이 생겼고, 히스토리가 없어 특정 커스텀이 왜 존재하는지 파악하기 어려웠으며 Dead Code도 방치되어 있었습니다.

훅 하나만으로 목록 페이지의 전체 커스텀 현황을 한눈에 파악

기획

경제 관념이 부족하면 성인이 되어서도 많은 제약과 불편함이 따릅니다. 특히 대한민국 학생들의 금융이해도 수준은 40점 안팎으로, 국가별 수준의 최하위에 위치하고 있습니다. 넘쳐나는 금융 정보들을 올바르게 활용하기 위해서는 어렸을 때부터의 교육이 중요하다는 연구 결과에 따라, 이를 도와줄 수 있는 서비스를 기획하게 되었습니다.

머핀(muFin)은 실생활에서의 경제 활동을 도와줄 수 있는 아동 전용 핀테크 서비스입니다. 기본적으로 송금과 용돈기입장 기능을 제공하며 날씨를 활용한 모의 주식을 통해 투자의 개념을 배울 수 있습니다. 또한 부모님과 연동된 적금, 대출 기능을 통해 쉽고 재미있게 경제 관념을 확립하도록 유도합니다.

서비스 기능

  • 부모님이 계좌를 개설한 후, 아이의 회원가입과 계좌 개설을 할 수 있다.
  • 개설된 계좌에서 서비스의 다른 유효한 계좌로 송금할 수 있다.
  • 부모님과 아이 계정은 서로 연동되어 아이들의 소비 내역을 파악할 수 있다.
  • 아이들은 용돈기입장 기능을 통해, 소비와 수입을 정리할 수 있다.
  • OCR 기능을 통해 영수증을 스캔하면 소비 내역의 자세한 내역을 자동으로 등록할 수 있다.
  • 부모님이 적금 상품을 직접 등록할 수 있다.
  • 아이들은 부모님이 만든 적금 상품 중 원하는 상품을 선택해서 가입할 수 있다.
  • 아이들이 돈이 필요할 때는, 부모님께 대출 신청을 할 수 있다.
  • 대출 신청서에는 대출의 목적, 금액, 기간, 불입일의 정보와 챗봇과의 대화를 통해, 대출이 정말 필요한지 스스로 판단할 기회를 제공한다.
  • 대출을 신청하게 되면, 부모님은 대출 신청서를 심사할 수 있다.
  • 대출 심사 결과로 승인 또는 거절을 선택할 수 있다.
  • 날씨와 주가를 연동시켜 모의 주식 서비스를 제공한다.
  • 아이들은 주식 차트와 날씨 정보를 기반으로 주식을 매도하고, 매수할 수 있다.
  • 주식에 투자하지 않는 돈은 파킹통장에 저축되어, 안정적으로 투자할 수 있다.
  • 투자 수익률로 전체 유저 중 내 순위와 전체 랭킹을 제공한다.

기획

인플루언서 또는 어떤 개인이 추첨 이벤트를 진행하려고 할 때 인터넷 방송 플랫폼이나 카카오톡에서 제공하는 기능을 주로 사용합니다. 하지만 이는 단순히 랜덤 또는 선착순 방식이기 때문에 재미 요소가 부족하다고 생각했습니다. 따라서 인플루언서의 시청자들, 또는 개개인이 능동적으로 재미있게 참여할 수 있는 추첨 이벤트 서비스를 기획하고자 했고, 여기서 새로운 게임을 통한 방법을 떠올렸습니다. 그 결과 대규모의 인원이 실시간으로 선착순 게임을 즐길 수 있는 서비스를 개발하게 되었습니다.

서비스 기능

  • 별도의 회원가입 없이 닉네임을 입력하여 로그인할 수 있다.
  • 닉네임마다 랜덤으로 고유한 색깔을 부여받고 이는 화면에 계속 표시된다.
  • 로비, 대기실, 게임 화면에서 채팅을 할 수 있다.
  • 로비 화면에서 생성된 방들을 확인하고 입장할 수 있다.
  • 호스트는 방 제목, 인원, 비밀 방 여부를 입력하고 방을 생성할 수 있다.
  • 방에 입장하면 대기실 화면으로 이동하며 참가한 플레이어 목록을 확인할 수 있다.
  • 호스트는 대기실에서 닉네임 가리기 모드 여부, 1라운드의 도발 멘트를 입력할 수 있다.
  • 도발 멘트는 게임이 진행되는 동안 상단에 보여지며, 1라운드를 제외하고 각 라운드의 우승자가 입력할 수 있다.
  • 대기실에서 게임 방법을 확인할 수 있고 호스트가 게임 시작 버튼을 누르면 5초의 카운트다운 후 게임이 시작된다.
  • 게임이 진행되면 킬로그에서 누가 누구를 공격했는지 실시간으로 확인할 수 있다.
  • 실시간 랭킹을 제공하여 누가 순위권에 오르는지 바로 확인할 수 있다.
  • 하나의 라운드가 종료되면 게임 시간, 생존 시간, 라운드 랭킹, 제거한 플레이어 수, 나를 제거한 플레이어의 닉네임 등의 결과를 확인할 수 있다.
  • 결과 확인 화면에서 30초의 카운트다운 후 다음 라운드가 자동으로 시작된다.
  • 게임이 종료되면 최종 결과를 확인할 수 있다.

성과 및 배운 점

  1. 도트 그래픽 스타일 UI의 재사용성을 높이기 위해 코너 영역만 이미지로 분리하고 내부 영역은 CSS로 렌더링하는 9-Slice Scaling 구조 설계
  2. WebSocket을 사용한 실시간 채팅 구현 및 사용자의 액션에 따른 실시간 이벤트 처리. 이때 전체 채팅 외에도 방 채팅 및 게임 라운드가 넘어갈 때의 채팅 기록 유지 등 다양한 상황 고려
  3. styled-components을 사용한 스타일링으로 CSS-in-JS 방식 경험
  4. 간단한 애니메이션 구현을 위해 framer motion을 학습하고 적용
  5. 백엔드 팀원 5명과 협업하며 혼자서 프론트엔드 개발을 담당함으로써 커뮤니케이션, 일정 관리, 통신 문제 발생 시 대처 능력 등의 소프트 스킬 향상
